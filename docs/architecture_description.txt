Architectural & Technical Specification1. System OverviewThis document specifies the technical architecture for a data-driven financial analytics platform. The system ingests external market data via API protocols and flat-file uploads, structures it inside a relational storage engine, processes it through isolated logic layers, and delivers a browser-based web application.2. Component Specifications2.1 Data Ingestion Subsystems2.1.1 API Data Pipeline (yfinance Ingestion Engine)File Classification: Separate Python Script (ingest_api.py)Functional Scope: Programmatic ingestion of equity and market indices.Process Sequence:Initialize connection to yfinance API via requests.Parse raw payload into a structured Pandas DataFrame.Perform temporal verification and clean missing values using numpy.Serialize memory-resident DataFrame to a localized physical staging .csv file.Bulk-insert the staging .csv dataset into target MySQL tables via a sub-process connection.2.1.2 Bulk CSV Upload EngineFile Classification: Separate Python Script (loader_csv.py)Functional Scope: Manual or automated file system ingestion.Process Sequence:Monitor file target vectors for newly initialized .csv uploads.Map variable delimited columns directly to corresponding MySQL relational fields.Execute transactional commits into the database engine.2.2 Core Dependencies & Environment (requirements.txt)The backend processing orchestration layer requires the following library definitions:textnumpy

Use code with caution.2.3 Storage TierEngine Type: Relational (RDBMS)Technology: MySQL DatabaseIntegration Vector: pymysql driver frameworkAccess Control: Isolated access patterns governed entirely by backend abstractions. No direct client-side visual query permissions.2.4 Processing & Visualization Engine2.4.1 Data Selection & Core Logic LayerFile Classification: Separate Python Script (logic_layer.py)Functional Scope: Query building, multi-table joining, mathematical transforms, and validation of analytical computations.2.4.2 Visualization & Web Serving LayerFile Classification: Separate Python Script (app_presenter.py)Functional Scope: Dynamic UI state compilation and charting engine orchestration.Driver Framework: Uses pymysql to pull clean query responses from the logic tier.Layout Generation: Employs streamlit and flask frameworks to define interface scaffolding.Graphic Generation: Renders data states into interactive HTML/SVG components via plotly.2.5 Client Presentation Tier (Frontend Webapp)The system compiles outputs down to standard web asset components executed directly inside native browser runtime engines:Structure Layer (index.html): Renders Document Object Model (DOM) layouts generated by presentation modules.Presentation Layer (style.css): Controls page rules, view grids, layout margins, typography, and dark/light color treatments.Behavioral Layer (app.js): Intercepts client interaction events, manages client-side chart behaviors, and handles asynchronous visual modifications.
